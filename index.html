Case Study

DEEP DIVE

Cowrie Honeypot & MySQL Log Pipeline

UTSA IS-3033 — building on a honeypot deployed in a prior lab.

Problem: A Cowrie SSH honeypot was already capturing raw session logs, but the logs alone made it hard to spot patterns across attempts — everything lived in flat text with no easy way to filter by username, success rate, or time.

Action: Verified SSH connectivity across the host, Parrot, and target server VMs, then installed and configured a MySQL database as Cowrie's output target so session data would land in structured tables instead of plain logs. Hit a snag when restarting the Cowrie service threw an error — resolved it by resetting the environment and re-verifying the configuration — then confirmed the pipeline by cross-checking the raw Cowrie log against the new MySQL output.

Result: Ended up with a queryable table of every login attempt — session ID, username, password, success/failure, and timestamp — that made patterns immediately visible: every successful login used "root," while failed attempts spanned several usernames and passwords, a clear brute-force signature. It's the same triage instinct a SOC analyst applies to real authentication logs, just built from scratch on a system I controlled end to end.
